# 外から来た色辞書の受け入れ手順

新しいデータをもらったら、**そのまま入れずに必ず点検する。**
良さそうに見えても、入れるとかえって質が下がることがある。

## なぜ点検するのか

このアプリは言葉をTOHOの実品番に翻訳する。
色が使い回されていると、**別の言葉なのに同じ品番ばかり出る**ようになり、
「その言葉のための色」という前提が崩れる。

実際にあった例:

| もらったデータ | 1項目あたりの専用色 | 何が起きるか |
|---|---|---|
| v1(332件) | 0.06 / 5 | 「クリーム#E8DFCC」だけで332項目中133項目に入っていた |
| 追加版(36件) | 0.19 / 5 | 家族とジョージアンが4色共通、カジュアルと家族が4色共通 |
| v2(240件) | 1.43 / 5 | 実質的に改善。国・地域だけ採用した |
| 自前の辞書 | 1.70 / 5 | — |

## 手順

### 1. 点検する

```
python3 tools/audit-incoming.py ~/Downloads/xxx.json
```

分野ごとに採否が出る。見ているのは5つ。

- **色の使い回し** — 1項目あたり何色がその項目だけの色か(1.00未満なら見送り)
- **項目どうしの近さ** — 無関係な言葉が同じ配色になっていないか
- **色名の質** — 「孔雀・主調」のような役割名になっていないか
- **説明文の質** — 全件が同じ穴埋めになっていないか
- **新規性** — すでにこちらが持っている語ではないか

色名が役割名だと、**画面に出したとき台無しになる**ので、
色が良くても「語彙だけ採用」に落ちる。

### 2. 採用する分野だけ下書きにする

```
python3 tools/json-to-csv-draft.py ~/Downloads/xxx.json data/entries-draft.csv
```

すでにある語は自動で落ちる。

### 3. ひとことと色を手で直す

外のデータの説明文は、たいてい穴埋めの定型文になっている。
このアプリは「眠らない街の残像、灯りが際立つ闇」のような一行を出すので、
**そのまま入れると見た目に後退する。**

### 4. 入れる

```
python3 tools/import-entries.py data/entries-draft.csv          # 点検だけ
python3 tools/import-entries.py data/entries-draft.csv --write  # 書き出す
```

品番の誤り・トーンや技法の表記ゆれ・既存辞書との重複を見て、
問題があれば日本語で言って止まる。

### 5. 壊していないか確かめる

既存のテーマの出力が変わっていないことを必ず確認する。
辞書に語を足すと、思わぬところで長い語の取り合いが起きる。

### 6. 依頼文と語彙一覧を必ず更新する ← 忘れやすい

取り込みが終わったら、**そのつど**この2つを更新する。
次の納品の質は、ここを怠るとそのまま落ちる。

```
node tools/dump-terms.js        # data/existing-terms.txt を更新(重複を防ぐ)
```

`docs/gpt-request-template.md` には、
- 実績表にその版の結果を1行足す
- 直っていた点は**お礼として明記する**(指摘が届いていることが伝わる)
- 新しく見つかった問題を書く。無ければ「新たな指摘はありません」と書く

直った点を書かないと、相手はどれが効いたのか分からないまま作業することになる。

## 採否の考え方

**語彙と色は別に評価する。**

外のデータは**語彙の選定が的確なことが多い**。
「どんな言葉を辞書に持つべきか」は貰う価値がある。
一方で色は、限られた色見本から組み合わせただけのことが多く、
そのまま入れると使い回しが持ち込まれる。

迷ったら **語彙だけ採り、色は自分で書く。**
